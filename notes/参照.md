# 参照仓库做法笔记

参照：Bowen1314/inkdove（本地 `reference/inkdove`，不进版本库）。只学工程做法，不学业务，不抄代码。每个阶段开工前重读本文件。

1. **规格先冻结接口与枚举，再写代码。** SPEC 开头声明“本文件是唯一契约：路由、字段名、枚举值必须一字不差”，并规定有歧义按最简单能跑通处理且必须记偏离。出处：`SPEC.md` 第 8 行。
2. **非目标写成可判定的清单，而不是口号。** README 的“适用于 / 不适用于”各列具体场景，明确不做什么。出处：`README.md` 第 34–47 行。
3. **所有配置统一前缀，只读自己的变量。** 明确禁止读取 `LLM_API_KEY`、`OPENAI_API_KEY` 等通用名，避免误用宿主环境里的密钥。出处：`SPEC.md` 第 33 行、`docs/development.md` 第 38 行。
4. **密钥只写不读。** 设置接口只返回 `apiKeySet` / `apiKeyLast4`，任何接口不回传明文，日志不打印。出处：`SPEC.md` 第 51、72、100 行。
5. **错误响应统一结构。** HTTP 4xx/5xx + `{error, code}`，错误信息中文可读、code 机器可判。出处：`SPEC.md` 第 56 行。
6. **每个接口都写失败分支和具体状态码。** 409（任务已在跑）、400（没有可处理资料 / 模型未配置）、404、429 等都逐条定义。出处：`SPEC.md` 第 124 行、`docs/deviations.md` 第 17–22 行。
7. **把“数字”写进规格。** 超时 60/180 秒、重试 2 次、并发 2、单条 2000 字符、每会话每小时 20 条、全局每分钟 30 条、资料 20MB、抓取 30 页。出处：`SPEC.md` 第 114–115、140、214、280、342 行。
8. **外部服务全部可替换成确定性 mock，一个环境变量切换。** `INKDOVE_LLM_MOCK=1` 时 distill/ask/审核都有固定规则；测试和演示不联网不花钱。出处：`SPEC.md` 第 49、345 行、`docs/development.md` 第 37 行。
9. **测试辅助注入时钟和等待时间，绝不 sleep 等结果。** `outreachNow`、`outreachIntervalMs`、`mockDelayMs` 由 `createApp` 选项覆盖；断言等条件成立（`waitFor`）。出处：`docs/deviations.md` 第 10 行、`server/test/f11.test.js` 第 118–128、158–161 行。
10. **测试按“失败模式”列，不只列正常路径。** 超时、429/5xx、格式不对、权限不足、输入非法、并发冲突、进程重启都要有对应用例。出处：`SPEC-phase2.md` 第 744–789 行。
11. **用假外部服务测协议细节。** 假 WAHA / 假 Meta 校验请求头、请求体、错误码；SMTP 用 nodemailer 的 stream/json transport，不连外网。出处：`docs/development.md` 第 40 行、`SPEC-phase2.md` 第 778–779 行。
12. **进程重启是正式测试场景。** 同一个数据目录重启后，running 的外联任务接着发；不是只测内存状态。出处：`server/test/f11.test.js` 第 752–790 行。
13. **状态机用真实数据库断言，不只看接口返回值。** 直接查 `llm_calls`、`muted_until` 等列，验证计数和闸门确实落库。出处：`server/test/abuse.test.js` 第 401–421 行。
14. **防滥用做多层，且失败时默认不发。** prompt 约束 + 程序硬规则 + 审核调用 + 频率闸门；审核失败/超时/解析不了一律 handoff。出处：`SPEC.md` 第 242–281 行、`server/test/abuse.test.js` 第 82–107 行。
15. **提示词泄露用每次启动随机金丝雀串检测。** 命中即 blocked，测试直接传固定 canary 验证。出处：`SPEC.md` 第 266 行、`server/test/abuse.test.js` 第 6、73–80 行。
16. **红线和价格核对用程序硬规则兜底，不只靠模型。** 金额/百分比必须原样出现在引用条目；折扣词、成交词、身份词都有中英文词表。出处：`SPEC.md` 第 296–301 行、`server/test/abuse.test.js` 第 174–283 行。
17. **界面设计先写“要去掉的东西”。** 明确列出窄卡片堆叠、标题前彩色图标、解释句、胶囊徽章、原生下拉框等，再写 token。出处：`DESIGN.md` 第 5–34 行。
18. **设计 token 写具体值，并给出对比度约束。** 两套颜色、字号阶梯、4px 间距、圆角与阴影用途、120/200ms 动效；页面 CSS 禁止写死颜色字号。出处：`DESIGN.md` 第 24–34、38–96 行。
19. **偏离规格逐条编号，写明原因和影响。** 包括“某路径没有自动化测试”“文档未核实”的诚实记录。出处：`docs/deviations.md` 第 5–40 行。
20. **外部接口先核实再写代码，记录链接、版本和实测日期。** 没实测的明确标“按文档写的，还没在真机上核实”。出处：`docs/external-apis.md` 第 5–40 行。
21. **提交说明写用户看得到的行为变化和关键数字。** 一条提交能说清“改了什么、对谁有用、边界是什么”，而不是“update code”。出处：`git log --format='%s'` 最近 60 条。
22. **版本发布由标签驱动且先校验一致性。** 推 `vX.Y.Z` 前检查标签与 package.json version 一致，再跑测试、构建、建 Release。出处：`docs/development.md` 第 43–53 行。
23. **安装文档从空环境可复现。** 前置条件、最少必填配置表、逐步命令、首次设置、升级、备份都写全。出处：`README.md` 第 94–197 行。
24. **测试文件名按功能域拆分，单个文件覆盖一条完整用户路径。** `distill.test.js` 从切块、启动、阶段推进、增量、重建到取消；`f11.test.js` 从解析、预检、分配、发送到重启。出处：`server/test/distill.test.js`、`server/test/f11.test.js`。


## 本项目额外照搬

25. **先搭测试地基再写功能。** 临时数据目录、假外部服务、请求封装、条件等待属于“第一个提交”，不等到功能写完再补。出处：`server/test/helpers.js` 的被所有测试文件复用方式。
26. **README 先写风险与边界。** “使用前须知”放在功能之前，不把风险藏到文档深处。出处：`README.md` 第 28–32 行。
27. **演示模式是产品的一部分。** 用 mock 生成可重复的示例数据，截图、测试、演示共用一套，不手工编数字。出处：`SPEC.md` 第 49、345 行。
28. **每个功能提交都同步文档。** 行为变化、接口变化、运维步骤同一条提交完成，避免 README 落后于代码。出处：`git log --format='%s'` 中多数功能提交同时提到“文档和测试”。

## 我明确不照搬的

- 不照搬它的业务（WhatsApp 客服、知识库蒸馏）、多容器部署和在线更新机制；本项目按自身形态选最简部署。
- 不照搬其 4200 行样式表先写后拆的过程；本项目从第一天就分 token/组件。
- 不引入它的重依赖栈（better-sqlite3、Express、React）；按本项目实际需要选依赖，能少则少。
- 不做“一人前端一人后端”的双端并行；本项目第一版按单进程 CLI + 本地单文件报告组织，减少接口面。
