# 真实使用记录

日期：2026-10-29
环境：从空目录克隆并 `pip install .` 的 CueLint 0.1.0（见 `notes/安装实录.md`），macOS / Python 3.13.5。
工作目录：`/tmp/cuelint-runs/real`。原始输出：`/tmp/cuelint-runs/real/session.log`。

共 11 次，包含 5 次失败路径（7–11）。

| # | 场景 | 命令 | 结果 |
|---|---|---|---|
| 1 | 干净中文字幕 | `cuelint check clean.srt` | 0 错误 0 警告，退出 0 |
| 2 | 问题样本 | `cuelint check examples/demo.zh.srt` | 3 错误 6 警告，退出 1 |
| 3 | 修复问题样本 | `cuelint fix examples/demo.zh.srt --force --report demo.html` | 修复 5 处，剩 1 错误 3 警告，退出 1 |
| 4 | 英文 VTT | `cuelint check bad.vtt` | 1 错误 1 警告，退出 1 |
| 5 | 用 latin 档修 VTT | `cuelint fix bad.vtt --profile latin --force` | 修复 2 处，剩 1 错误，退出 1 |
| 6 | 两文件 JSON | `cuelint check clean.srt bad.vtt --format json` | 2 文件，退出 1，summary 正确 |
| 7 | 文件不存在（失败） | `cuelint check nope.srt` | 退出 2，`input_not_found`，指出路径 |
| 8 | SRT 坏时间行（失败） | `cuelint check malformed.srt` | 退出 2，`parse_error`，指出行号 1 |
| 9 | 非法时长 fix（失败） | `cuelint fix invalid.srt` | 退出 1，`unfixable_timing`，不写文件 |
| 10 | 输出已存在（失败） | `cuelint fix clean.srt` | 退出 3，提示 `--force` |
| 11 | 非法后缀（失败） | `cuelint fix clean.srt --suffix .bad` | 退出 2，提示 1–20 字符 |

## 观察

- 第 4/5 条会留下一个 `cps-too-high`：80 字符 / 2 秒，即使拆段和延长也无法降到 9 CPS；这属于“修不了，必须指出”的情况，符合规格。
- 第 3 条同样留下 1 个错误（过长 cue 98 CPS，拆段会更差）和 3 个警告。
- 第 10 条先手动跑了一次 fix 生成输出，再跑一次触发“已存在”；这是有意的失败用例。
- 所有失败路径都只写 stderr，退出码与 SPEC 一致；`--format json` 的错误对象已在测试中覆盖。
