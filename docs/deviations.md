# 与规格的偏差

按出现顺序编号。每一条都说明原因和影响；没有“秘密行为”。

## 1. 原子写的临时文件名

SPEC 7.6 写的是同目录 `.cuelint-<pid>-<n>.tmp`。实现用 `tempfile.mkstemp(dir=..., prefix=".cuelint-", suffix=".tmp")`，文件名含 pid 和随机后缀，不是递增序号。

原因：`mkstemp` 原子创建并避免竞态；序号需要额外锁。影响：失败时可能残留文件名不同的临时文件；写入成功后都会被 `os.replace` 清掉。测试覆盖“不可写目录不留下临时文件”。

## 2. VTT 头部的序列化

输入 `WEBVTT - demo` 解析为 `header_lines=["- demo"]`；输出写成两行：

```text
WEBVTT
- demo
```

SPEC 7.4 要求先写 `WEBVTT`，再逐行写 header。影响：VTT 输出不是输入字节级复制；第一次输出后再解析再序列化保持稳定。

## 3. 时间码补零

输入 `1:02:03,004` 或 `00:01.000` 会被接受，输出统一补成 `01:02:03,004` / `00:00:01.000`。SPEC 7.4 要求 `HH:MM:SS`。影响：输出更规范，但不是原样保留。

## 4. 颜色只用于问题标签

`CUELINT_COLOR=always` 时只给 `[错误]` / `警告` 标签上色，标题和统计行不着色。SPEC 3.1 只要求“使用 ANSI 颜色”，没有规定范围。影响：重定向到文件时颜色仍会存在（`always` 的语义），JSON 永远无色。

## 5. `<i>` 跨行与拆段

断行时会在每行闭合并重开 `<i>`/`<b>`/`<u>`；拆段时跨片段携带未闭合的简单标记。复杂标记（`<font>`、`{\...}`）不修、不拆，保持原样并报 `complex-markup`。

SPEC 12.3 要求“`<i>` 跨行闭合重开”；实现覆盖了行内和拆段。影响：简单标记被规范化，复杂标记完全不动。

## 6. `--version` 也会校验环境变量

`main()` 在解析子命令前读取 `CUELINT_COLOR`，因此 `CUELINT_COLOR=bogus cuelint --version` 退出 2，而不是打印版本。SPEC 只要求非法值退出 2，没有规定 `--version` 的优先级。影响：CI 里环境变量写错会尽早暴露。

## 7. 报告写入失败时字幕已预检但未写

`fix` 先预检所有输出和报告路径，再写字幕，最后写报告。报告写入失败退出 3；已写的字幕输出保留。SPEC 7.6 要求报告原子写，没有要求回滚字幕。影响：极端磁盘错误下可能留下字幕但没有报告；不会留下半个报告。

## 8. 没有平台认证阈值

四个档位的数字是 CueLint 默认值，不是 YouTube/Netflix/B 站等平台的官方限制。SPEC 和 README 都明确写了这一点。影响：用户不应把“CueLint 通过”当成平台审核保证。

## License

选择 MIT 而不是 AGPL：CueLint 是本地 CLI，没有网络服务，不存在“修改后必须回馈服务端”的场景；MIT 降低个人创作者和小团队的使用门槛。代价是别人可以闭源分发修改版；对 0.1.0 的工具项目，这个代价可接受。

## 9. 修复输出的时间戳钳制到全局上限

SPEC 4.x 规定时间戳必须在 0–3599999999ms。修 `duration-too-short` / CPS 时，实现把延长上限再与 `MAX_MS` 取小；SPEC 第 5 条规则只写了“上限为 `next.start_ms - min_gap_ms` 或 `start_ms + max_duration_ms`”，没写全局上限。

原因：不钳制会写出解析器拒绝的时间戳，`fix` 的输出下次 `check` 直接 `parse_error`。影响：极靠末尾的字幕最多只延到 999:59:59,999，而不是超过它。测试覆盖 `tests/test_fixer.py::test_fix_never_writes_timestamp_over_parser_limit`。
